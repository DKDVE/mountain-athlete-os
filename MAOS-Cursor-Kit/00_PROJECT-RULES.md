# MAOS — Cursor Project Rules (the constitution)

You are building **Mountain Athlete OS**, a production-grade PWA for hybrid-athlete tracking. These rules override any default behavior and apply to every task in this repo.

## Prime directives
1. **No patchwork, no deferral.** Never leave `TODO`, `FIXME`, placeholder returns, `throw new Error("not implemented")`, commented-out code, mock data in shipped paths, or "we'll wire this later". If a task can't be completed properly, stop and report why — do not fake it.
2. **Every task ends green.** A task is complete only when `pnpm typecheck && pnpm lint && pnpm test && pnpm build` all pass, and new logic is covered by tests. Run them before declaring done. Paste the passing output.
3. **Contracts are law.** `/docs/CONTRACTS.md` defines the DB schema, TypeScript domain types, API shapes, env vars, and the dashboard widget registry. Do not invent divergent shapes. To change a contract, follow "Contract change protocol" below — never silently.
4. **Vertical slices only.** Ship one capability end to end (DB → API/query → state → UI → test → deploy) per phase. No horizontal "build all the components then wire later".
5. **Ask zero-ambiguity questions only when blocked by a genuine contradiction.** Otherwise proceed using the contracts and these rules; state assumptions in the PR description.

## Stack (pin latest stable at Phase 0, record versions in /docs/VERSIONS.md)
- **Frontend:** Vite + React + TypeScript, built as an installable **PWA** (vite-plugin-pwa, Workbox). Deployed to **GitHub Pages** (static). Use **hash-free routing via a 404.html SPA fallback**, base path set to the repo name.
- **Styling:** Tailwind CSS with tokens from CONTRACTS (monochrome). **shadcn/ui** primitives, themed. No component library other than shadcn + our own.
- **State/data:** TanStack Query for all server data; Zustand for ephemeral session/UI state (logger, timers). **Supabase JS client talks directly from the browser** (auth + CRUD), secured by RLS. Never route CRUD through Render.
- **Local-first:** Dexie (IndexedDB) mirror for the active program + a mutation **outbox**; background sync on reconnect; deterministic ULID client ids so writes are idempotent.
- **Backend (Render):** a thin **Node + Fastify + TypeScript** service. Its ONLY jobs: (a) proxy OpenRouter with the secret key, (b) validate the caller's Supabase JWT, (c) run scheduled jobs (nightly derived-metrics recompute). No business data flows through it that Supabase could serve directly. Assume Render free tier cold-starts — never block user logging on it.
- **DB/Auth:** Supabase (Postgres + Auth + Storage + RLS). **Multi-tenant from row zero:** every user-owned table has `user_id uuid references auth.users` and an RLS policy `user_id = auth.uid()`.
- **AI:** OpenRouter via the Render proxy, model id `openrouter/free` (auto-routes to a capable free model), **always** using `response_format: json_schema` with a strict schema. Validate every AI response against the schema with Zod before use; a schema failure is a handled error, never a crash and never applied.

## Repository conventions
- Package manager **pnpm**, monorepo via pnpm workspaces: `apps/web` (frontend), `apps/api` (Render service), `packages/shared` (Zod schemas + TS types generated/derived from CONTRACTS, imported by both).
- **Single source of types:** DB types generated by `supabase gen types typescript`; domain/validation types are Zod schemas in `packages/shared` that infer TS types. Both apps import from `packages/shared` — never redeclare a shape.
- Path aliases (`@/…`, `@shared/…`). Absolute imports only for cross-package.
- **Feature-folder structure** in `apps/web/src/features/<feature>/{components,hooks,queries,store,types,index.ts}`; shared UI in `src/components/ui`; app shell in `src/app`.
- Env: public browser vars prefixed `VITE_`; secrets live only in Render/Supabase, never in the frontend bundle, never committed. `.env.example` lists every var.

## Quality bar (non-negotiable, checked at every gate)
- **TypeScript strict** (`strict: true`, `noUncheckedIndexedAccess: true`). No `any` except at typed boundaries with a comment justifying it. No `@ts-ignore` without a one-line reason.
- **ESLint + Prettier** enforced; lint must pass with zero warnings-as-errors config.
- **Tests:** Vitest for units/logic, React Testing Library for components, Playwright for the 3 critical E2E flows (log a workout, log a run, AI edits dashboard). Every phase adds tests for its logic. Coverage on `packages/shared` logic ≥ 90%.
- **Error handling:** every async path has explicit error and empty states in the UI (skeletons for loading, empty-state components, retryable error toasts). No unhandled promise rejections. Supabase/API errors are typed and surfaced, never swallowed.
- **Accessibility:** semantic HTML, keyboard operable, visible focus rings, AA contrast, touch targets ≥ 44px, `aria-live` for timers. Run axe in component tests for interactive screens.
- **Offline:** any logging UI (workout, run, meal, check-in) must fully function offline and reconcile on reconnect. This is tested, not assumed.
- **Performance budgets:** initial route JS < 200KB gzipped (code-split by route); charts lazy-loaded; Lighthouse PWA + Performance ≥ 90 on the deployed build.
- **Security:** RLS on every table (verified by a test that a second user cannot read row of the first). Render verifies JWT on every request. No secrets in client. CORS locked to the Pages origin.

## Contract change protocol
If a phase genuinely needs a new column/type/endpoint: (1) update `/docs/CONTRACTS.md` in the same PR, (2) add a forward Supabase migration (never edit an applied migration), (3) regenerate types, (4) update `packages/shared`, (5) note it in the PR under "Contract changes". Additive only unless explicitly told otherwise.

## Definition of "done" for any task
Green typecheck + lint + tests + build; new logic tested; loading/empty/error states present; a11y checks pass; offline works where relevant; deployed preview updated; PR description lists what shipped, assumptions, and any contract changes. If any item is missing, the task is not done.
